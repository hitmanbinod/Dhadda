## Web files that exist in this repo

- `web/index.html` — stock Flutter Web shell (`<title>expense</title>`).
- `web/manifest.json` — branded PWA manifest (Dhadda, #009688).
- `assets/webapp/` — compiled Flutter Web bundle (1.5.0+4), generated by
  `dart tool/build_embedded_web.dart`; do not hand-edit.
- `lib/data/prefs_domain_store.dart` — web data backend using localStorage.

There is **no** `ui.css`, `renderHome`, `editorHTML`, `S/U/load/save/seed`
state layer, or `design/` folder (before this recon). The whole Flutter Web
app is rendered by the same Dart widgets as Android.

## Disagreements / blockers (keep for final report)

1. **No JS/DOM web UI exists in this repo** — the described app (ui.css,
   renderHome, editorHTML, state layer) is the mock prototype only.
2. **"Do not edit Android code" vs "rebuild the web presentation"** — Flutter
   Web and Android share the same Dart widget files; a Flutter-web restyle
   would necessarily edit Android UI code.
3. `design/reference/dhadda-mock.html` was absent; copied from the Downloads
   copy as instructed.
4. Settings is already not a tab in Android (pushed route) — agrees with brief.
5. Android Home *does* have Budgets and Events (default visible) and Today
   ring / Daily rhythm / Forecast (hidden by default); no "cash flow" card.
6. Mock Home has a "daily allowance" ring and rhythm bars that Android has as
   optional hidden sections; port only if enabled in the user's layout.

## Blocking question for the maintainer

Which app is the "web UI" to restyle? (a) the Flutter Web app in this repo,
which requires relaxing the no-Android-edits rule, or (b) a new standalone
DOM web app based on the mock, in which case the mock's localStorage layer is
the only data layer available and the "don't port the state layer / don't
change the data layer" rules conflict. Phase 1 not started.
